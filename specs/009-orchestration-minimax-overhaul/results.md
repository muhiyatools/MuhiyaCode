### Trace-driven post-run corrections

The successful run proved the phase gates but exposed a double-execution seam:
after full delegated implementation + validation reached `done`, the legacy
saved-plan brief re-injected the full plan, so the main model repeated edits,
checks, and an auto-review. The final implementation now:

- suppresses that legacy payload after a successful full pipeline;
- tells the planner to consume banked findings without re-reading covered files;
- preserves `Verification:` / `Risks:` when a later `update_plan` omits `note`;
- reports the exact missing plan-bar component and keeps targetless global checks
  in the note rather than as implementation steps;
- gives validation a compact step/check brief plus gate-checked read-only shell
  commands, and bounds reports returned to the parent conversation;
- resets `phase=done` before a fresh direct task.

These corrections are covered by scripted regression tests, including an
end-to-end assertion that a successful full pipeline never sends
`[executing saved plan]` to the main model. Per the budget-conservation rule, no
third paid DeepSeek run was made, so the 22,133/30 figures above remain the last
LIVE measurements and SC-003/SC-004 are **not** retroactively claimed as passing.

## Post-implementation audit & polish (2026-07-15, independent review pass)

Nine-angle review (line-by-line, removed-behavior, cross-file, DeepSeek-cache
invariants, reuse, simplification, efficiency, altitude, constitution) with
grouped adversarial verification over both repos, plus three traps reproduced
from a LIVE user session. All fixes verified by the full suites (green in both
repos) and pinned with regression tests.

**DeepSeek protection (the audit's #1 mandate):**
- FIXED gateway `thinking.go`: unset effort was force-injecting
  `thinking:{type:"disabled"}` into DeepSeek reasoner requests (pre-009 they
  passed through and reasoned). Unset now passes through byte-identically;
  only an explicit none/off disables. The rewritten test and the "BEFORE"
  golden had both pinned the regressive behavior — corrected, and the goldens
  were regenerated with a documented `DEEPSEEK_GOLDEN_UPDATE=1` path
  (reasoner-absent scenario added).
- FIXED gateway `handler.go`: frequency/presence-penalty stripping was applied
  to EVERY OpenAI-dialect upstream; now DeepSeek-only (its documented purpose).
- VERIFIED SAFE: pipeline state rides the message tail only (never the stable
  prefix); one sanctioned prompt epoch; DeepSeek strip-on-replay byte-identical;
  `repairToolMessageSequence` provably a no-op on valid histories; per-key
  `user_id` injection invariant within a session.

**Live-session traps (reproduced from the user's CapCut-clone run):**
- FIXED plan content bar deadlock: `exit_plan_mode` could be rejected forever
  (one gap reported per attempt — whack-a-mole across steps 1→7→11). Now ALL
  gaps are listed in one guidance message with the exact required step shape,
  at most TWO guidance rounds, then the bar is waived with a recorded plan-phase
  degradation (PL-8) — the human approval pause remains the real quality gate.
- FIXED planMode↔pipeline desync stall: `exit_plan_mode` returned "not in plan
  mode" while the pipeline phase gate kept blocking every edit — no escape. The
  pipeline plan phase is now exitable regardless of the legacy flag.
- FIXED research over-fan-out: five near-identical generic research lenses
  burned ~915k tokens re-reading a 14-file repo. Generic fallback lenses capped
  at three (structure / change surface / acceptance); explicit user-named
  directory scopes still fan out per directory.

**Pipeline lifecycle (audit-confirmed deadlocks):**
- FIXED: a plan deferred at the approval gate leaked into the next unrelated
  task (approval text injected, all edits blocked). The pipeline now parks; the
  plan stays pending and resumable with "proceed".
- FIXED: `/plan clear` left the pipeline gating active for the discarded plan
  (hard deadlock). DiscardPlan now releases the pipeline.
- FIXED: a superseded/discarded plan could be revived into execution through a
  stale approval modal (terminal-guard bypass). Guarded in ApprovePipeline and
  pipelineTransition.
- FIXED: pipeline depth was not persisted — light pipelines resumed as full
  (unscoped subagent spend). Depth now rides the sidecar.
- FIXED: implementation/review reports (and stale pre-edit findings) satisfied
  the plan's research-evidence gate; grounding now counts only current-epoch
  research-phase findings.

**TUI agent views (user-reported, verified in code):**
- FIXED: keyboard view switches (Tab / Alt+N / Esc) never repainted the
  transcript body — dead once the task was idle. A view switch now marks the
  frame dirty, opens detail views at the top, and resumes bottom-follow on
  return to the main session.
- FIXED: tool rows inside a subagent view were inert (chips registered only in
  the main transcript); they are clickable/expandable everywhere now.

**MiniMax billing/detection hardening:** the >512k M3 pricing tier now uses
named constants and prefix-based family matching (variant rows like a future
`minimax-m3-highspeed` stay tiered; M2.x never matches — regression-tested,
SIMULATED figures only); the fresh-install default pairing reuses the exported
gateway M3 detector (bare "M3" catalog names pair correctly).

**Cleanups:** dead `ImplementationReady()` removed; duplicate report-banking
branch collapsed; no-op `reasoning_split` delete removed; duplicated ~4k-char
research briefing no longer sent on two consecutive turns; internal subagent
launches skip the JSON round-trip; diff line-counting no longer misreads
`++x;`/`--x;` code lines as headers; npm self-dependency removed.

**Deliberately skipped:** memoizing the per-turn tool-definition size probe
