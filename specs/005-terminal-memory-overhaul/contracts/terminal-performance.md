# Contract: Terminal Performance, Paging, and Frame Stability

**Feature**: `005-terminal-memory-overhaul`  
**Status**: Normative

## 1. Measurement boundaries

| Metric | Start | End | Gate |
|---|---|---|---|
| Input echo | Bubble Tea input event received by model | first composed frame containing the edit is handed to renderer; real-terminal trial additionally ends when captured terminal frame contains it | P95 <=16 ms for 10 and 5,000 events; P95 gap <=2 ms |
| Stream update | coalesced chunk delivered to model | frame containing chunk handed to renderer/captured | 5,000-event P95 no more than 5 ms slower than 10-event P95 |
| Resume input-ready | process start | shell accepts draft edits | P95 <=2 s over 30 reference-Windows trials |
| First resumed key | key received after process start | first frame containing key | P95 <=16 ms |
| Idle CPU | start/end OS process CPU seconds across unchanged 60-second wall interval | derived `(CPU_seconds / 60) * 100` | <=1% of one core; do not divide by machine core count |
| Working memory | OS WorkingSet/RSS samples every 5 seconds | maximum and final-15-minute trend | <=300 MiB; final 15-minute growth <=10% |

Go heap/allocation metrics are diagnostic and MUST be reported but MUST NOT be substituted for process WorkingSet/RSS.

## 2. Transcript page interface

The presentation state requests pages with:

- `session ID` and `generation`;
- direction (`initial-tail`, `before`, `after`);
- exclusive stable event cursor;
- entry limit and raw-byte budget.

The state layer returns ascending stable IDs, `hasOlder/hasNewer`, and total loaded bytes. Offset pagination is prohibited. A result with a stale session/generation is discarded without changing the frame or anchor.

Default retained-window limits:

- 384 entries;
- 8 MiB raw presentation content;
- 8 MiB rendered-block data;
- visible page plus at most one overscan page on each side.

One oversized visible/active entry may exceed a single page budget but is row-windowed and must not cause distant pages to remain retained.

## 3. Stable anchor and follow-output

- Scroll position is `event ID + intra-entry row`, not a global offset into all history.
- Wheel/PageUp/Up away from the newest content sets `followOutput=false`.
- New stream/tool rows do not change an anchored-away viewport.
- End/follow action or scrolling to the newest row sets `followOutput=true`.
- Prepending older pages compensates the anchor so the same visible row remains under the same screen coordinate.
- Resize recomputes wrapping and the anchor atomically; no intermediate old/new geometry frame is emitted.
- A session switch increments generation, clears live reconciliation and selection, and prevents stale async results from appearing.

## 4. Render invalidation

| Event | Allowed dirty scope | Prohibited work |
|---|---|---|
| text key/edit | input, command menu when slash matching changes | transcript page fetch/render |
| paste block mutation | input and its hit map | completed transcript render |
| assistant stream | active assistant block, activity, affected visible rows | completed block rerender |
| tool output | active tool block/activity | scan/rebuild all tools |
| wheel/page scroll | transcript window/anchor and frame hit map | input mutation |
| command/modal selection | affected overlay/status/input | completed transcript render unless viewport height changes |
| resize | one layout transaction, visible/overscan blocks, interaction map | multiple externally visible intermediate frames |
| idle/no external event | none | timer message, layout, SetContent, full-frame sequence increment |

Completed immutable entry row hashes MUST remain identical across stream updates elsewhere in the frame.

## 5. Timer lifecycle

- No base/global tick exists.
- Spinner/elapsed timer exists only while at least one visible animation requires it and stops on the terminal event.
- Notice expiry is one command scheduled at its deadline; replacement/cancellation makes the old deadline a no-op.
- MCP refresh remains scoped to the live MCP modal.
- Assistant and tool stream flush commands exist only while a buffer is non-empty and schedule at most one outstanding flush per source.
- Terminal cursor behavior generated by the renderer/terminal is outside the application-frame count but is noted in evidence.

## 6. Two-stage startup

1. Resolve minimal config, canonical workspace/session identity, theme, and empty composer.
2. Start the full-screen program and accept/edit draft input.
3. Hydrate engine, boot project context, sidecars, and initial transcript tail asynchronously.
4. Until runtime-ready, submission is retained and clearly marked waiting; it is neither lost nor sent twice.
5. Runtime/page completion carries the active session generation.
6. A cached web capability snapshot may be used for this session; network refresh cannot block the first input frame and applies only at a deliberate future boundary.

Simple/non-TTY/one-shot execution may remain synchronous but shares project-context construction and persistence.

## 7. Terminalbench fixture and evidence

`benchmarks/terminalbench` generates a fixed-seed workspace/session rather than committing a huge session. The 5,000-event fixture MUST populate:

- SQLite session plus 5,000 mixed user/assistant/tool/agent/status/error events;
- session transcript JSONL;
- realistic context-bounded `history.json` with tool-call/result pairs;
- knowledge, usage, and invalidation sidecars;
- large individual messages/tool outputs;
- live streaming, collapsed/expanded, scrolling, editing, and resize actions.

Every result JSON includes:

- scenario, run count, fixture seed/hash, event count and payload bytes;
- build label, commit, dirty flag, Go version, OS/arch, machine CPU/RAM;
- terminal name/version for physical trials;
- terminal width/height and theme/color mode;
- raw samples plus p50/p95/p99;
- frame count, dirty-pane count, rendered bytes and completed-row hash violations;
- process CPU seconds, WorkingSet/RSS samples, Go heap/allocation samples;
- errors, crashes, stale-page drops, duplicate/missing event count.

Baseline and improved evidence must use clean recorded commits/worktrees and identical fixture/machine settings. The current dirty development tree is not a valid baseline.

## 8. Required automated assertions

- 10 vs 5,000 input work stays within gates and input does not fetch/render transcript pages.
- Stream dirties one active entry; completed row hashes do not change.
- Scroll-away remains anchored during streaming.
- Page eviction meets entry/byte budgets and releases associated hit/cache data.
- Stale session-generation page/runtime results are ignored.
- Idle has no scheduled application command/frame.
- Resize emits one coherent geometry and preserves draft/paste/selection/anchor state.
- Live event persistence reconciles identity without duplicate rows.
